Can a frontier agent run an airline's
disruption desk for one day?

A fictional Helsinki airline has a day of cancellations, missed connections and scarce seats. Keep passengers moving from 06:00 to 23:00 using the same tools as a scripted reference desk. Every score comes from simulated passenger arrivals.

Current world v3. One completed OpenCode/Harbor model run, gpt-4.1-mini, scored 0.000 after stopping at 07:00 before rebooking. Stronger-model and repeated-run evidence is pending; a frontier gap is unmeasured.

Read the evidence ledger · Inspect run files

Recovery scores

Score = share of the reference desk's recovery achieved. Doing nothing = 0, reference = 1. Same seed, same disruptions, every run.

Coherence through the day

Value secured so far, hour by hour: what the day would end with if the desk walked away at that moment. Watch where the lines separate.

Alert by alert

For the bookings each alert broke, how much of the reference's recovery the agent achieved.

Named failure modes

Recomputed from logged actions with the current diagnostic code. Original scored Harbor reports stay unmodified. Value lost is measured against the reference, booking by booking.

Reward integrity

Current-world attacks against the verifier, standard size, seeds 1–3. Raw scores below retain losses and expose any reference weakness.

Run it

git clone https://github.com/13shreyansh/ops-desk-bench && cd ops-desk-bench
python -m opsdesk.eval --size standard --seeds 1 2 3          # reference, do-nothing, stop-early, naive
python -m opsdesk.experiment --suite scripted               # versioned baseline + exploit evidence
python -m opsdesk.experiment --suite harbor --agent oracle  # Harbor reference over MCP
