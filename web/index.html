AURORA REGIONAL · HEL OPS CONTROL · DAY 1

Can a frontier agent run an airline's
disruption desk for one day?

Ops Desk is a deterministic, long-horizon environment. Nine disruptions hit a hub between 06:00 and 23:00. The agent must keep ~1,000 bookings moving on scarce seats. A 150-line scripted desk that uses the same tools sets the bar. The frontier agent consistently falls short of it, and the code says exactly why.

01 The gap

Score = share of the reference desk's recovery achieved. Doing nothing = 0, reference = 1. Same seed, same disruptions, every run.

02 Coherence through the day

Value secured so far, hour by hour: what the day would end with if the desk walked away at that moment. Watch where the lines separate.

03 Alert by alert

For the bookings each alert broke, how much of the reference's recovery the agent achieved.

04 Named failure modes

Detected by code from the action log and the final world state, not by an LLM judge. Value lost is measured against the reference, booking by booking.

05 Reward integrity

Attacks we ran against our own verifier (standard size, seeds 1–3). None beats doing the job.

06 Run it

git clone https://github.com/13shreyansh/ops-desk-bench && cd ops-desk-bench
python -m opsdesk.eval --size standard --seeds 1 2 3          # reference, do-nothing, stop-early, naive
python -m opsdesk.make_harbor --seeds 1 2 3                   # Harbor tasks with an MCP sidecar
harbor run -p harbor/tasks/ops-desk-standard-seed1 -a oracle  # reference over MCP -> 1.0
